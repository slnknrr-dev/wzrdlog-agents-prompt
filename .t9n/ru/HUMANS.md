# HUMANS.md — что промпт WZRDLOG делает для вас

`AGENTS.md` — промпт для ИИ-агентов, которые пишут код. Этот файл объясняет его людям.
Агентам запрещено читать этот файл, так что здесь можно писать что угодно.

## Коротко

Агент ведёт свои рабочие заметки в файлах `WZRDLOG*`: задача, roadmap, что не сработало,
что сработало, известные ограничения, переиспользуемые фрагменты и словарь ваших слов.
Заметки лежат рядом с кодом и версионируются в отдельной **только локальной** git-ветке `WZRDLOG`.
Ваша настоящая история остаётся чистой, без вашей просьбы ничего не пушится,
а в любой новой сессии агент продолжает с того места, где остановился.

## Что вы получаете

- **Память между сессиями.** Новая сессия читает заметки и продолжает работу. Объяснять проект заново не нужно.
- **Чистая история.** `WZRDLOG*` в `.gitignore`. Заметки не попадают ни в ваши ветки, ни в npm-пакет.
- **История самих заметок.** Каждое изменение заметок — коммит в ветке `WZRDLOG`: их можно просматривать, сравнивать и восстанавливать.
- **Никаких случайных публикаций.** Агент никогда не предлагает push. Хук `pre-push` отклоняет любой push ветки `WZRDLOG`.
- **Говорите как удобно.** Агент сопоставляет ваши слова с постоянными терминами (`WZRDLOG_AND_TERMS.md`). Можно сказать «логин», «вход» или «auth», а файлы всё равно будут названы единообразно.
- **Неудачи запоминаются.** Тупиковые пути записываются, и агент перечитывает их перед новой работой, чтобы не повторять.
- **Измеримые фрагменты.** Переиспользуемые куски несут свой размер в имени файла (см. ниже).
- **Ваш язык.** Агент отвечает на том языке, на котором вы начали, и не меняет его, пока вы не попросите.

## Файлы

| Файл | Что в нём | Стоит ли читать? |
|------|-----------|------------------|
| `WZRDLOG.md` | Текущая задача и её статус | Да, чтобы видеть, чем, по мнению агента, он занят |
| `WZRDLOG+roadmap.md` | План текущего эпика со ссылками | Да |
| `WZRDLOG+roadmap-<n>-<epic>.md` | Планы завершённых эпиков | Когда нужно оглянуться назад |
| `WZRDLOG_BY_OPERATOR.md` | Ваши предпочтения | **Редактируйте его**, чтобы поменять умолчания агента |
| `WZRDLOG_AND_TERMS.md` | Ваши слова → термины агента → где искать | Полезно, когда агент вас не так понимает |
| `WZRDLOG+failures*.md` | Что не сработало, а также отложенное и заглушки | Хороший материал для ревью |
| `WZRDLOG+limitations*.md` | Известные принятые проблемы и подводные камни | Перед тем как полагаться на функцию |
| `WZRDLOG+successes*.md` | Что сработало, принципы, быстрые пути | Чтобы узнать удачные приёмы проекта |
| `WZRDLOG+<topic>-<theme>.md` | Проектирование по темам | Когда работаете над этой темой |
| `WZRDLOG+<action>-<result>-<N>.<ext>` | Переиспользуемые фрагменты кода или разметки | Копируйте свободно |
| `BACKLOG*.md` | **Публичный** короткий список дел для разработчиков | Ваш; агент его не трогает |

Failures или limitations: если что-то *можно* исправить, но не исправлено (неудачная попытка, отложенная работа, заглушка), это failures. Если это принято как есть, это limitations.

## Типичные случаи

**Старт в новой папке.**
Агент проверяет, что папка разумная (не домашний каталог и не корень диска), и выполняет `git init`.
Он добавляет `WZRDLOG*` в `.gitignore`, ставит защиту от push, один раз спрашивает о языке и дизайне
и сообщает о локальной ветке `WZRDLOG`.

**Возвращение на следующий день.**
Новая сессия восстанавливает недостающие файлы заметок из ветки `WZRDLOG`, читает задачу, roadmap и неудачи и продолжает работу.

**Вы прервали агента, или сессия оборвалась.**
Агент сохраняет заметки и помечает задачу `interrupted: <где>`. Свои изменения кода он коммитит как `WIP: …`.
Если позже он найдёт незакоммиченные изменения, которые делал не он (возможно, ваши), он **спросит**, прежде чем их коммитить.

**Переход к новому большому этапу (эпику).**
Старый roadmap архивируется как `WZRDLOG+roadmap-<n>-<epic>.md` с привязкой к точному коммиту файла задачи.
Начинается новый roadmap, и агент сначала перечитывает неудачи.

**В проекте уже есть незакоммиченный `BACKLOG.md`.**
Агент коммитит его как есть, переписывает в короткий понятный разработчику список, коммитит результат и строит по нему свои заметки.
Когда `BACKLOG.md` уже отслеживается в git, агент его не трогает, пока вы не попросите.

**Вы просите сделать push.**
Агент пушит только ту ветку, которую вы назвали, никогда не использует `--all` или `--mirror` и никогда не пушит `WZRDLOG`.

**Вы публикуете в npm.**
`WZRDLOG*` добавляется в `.npmignore`, только если этот файл уже существует. Агент никогда его не создаёт:
новый `.npmignore` заставил бы npm игнорировать ваш `.gitignore`, и в пакет могли бы уйти, например, `.env`.

**Заметки становятся длинными.**
Агент коммитит, сокращает файл и оставляет ссылки вида `WZRDLOG+failures.md@abc1234:L12-L30`.
Ничего не теряется: выполните `git show abc1234:WZRDLOG+failures.md`.

## Фрагменты и число в их имени

`WZRDLOG+substr-domain-13.js` означает: действие (`substr`) даёт результат (`domain`) с помощью **13 строительных блоков**.
Каждый фрагмент начинается со списка `contains:`, и число — это просто длина этого списка, так что проверить его может любой.

- Меньше число — проще версия. Когда агент оптимизирует `…-13.js` в `…-7.js`, старый файл остаётся в истории `WZRDLOG`, а выигрыш записывается в successes.
- Если число растёт, агент обязан записать причину.
- Это работает для любого типа файлов, например `WZRDLOG+mockup-login-9.html` для мокапа из 9 компонентов.

## Дизайн по умолчанию

Применяется только к проектам с интерфейсом: прямые углы, без градиентов, цвета морской волны и бирюзовый,
светлая и тёмная темы с самого начала. Чтобы изменить это, впишите свои правила в `WZRDLOG_BY_OPERATOR.md`, например:

```md
ui-design: rounded corners allowed; brand color #FF5500
```

## Полезные команды

```bash
git log --oneline WZRDLOG
```

```bash
git show WZRDLOG:WZRDLOG.md
```

```bash
git diff WZRDLOG~1 WZRDLOG
```

Резервная копия заметок, ведь они никогда не пушатся:

```bash
git bundle create wzrdlog-backup.bundle WZRDLOG
```

Восстановление из этой копии в другом клоне:

```bash
git fetch wzrdlog-backup.bundle WZRDLOG:WZRDLOG
```

## Что нужно знать

- Заметки существуют только на вашей машине. Удалите папку или `.git`, и они исчезнут. Если они важны, делайте bundle-копию.
- `git clean -fdx` (а также `-X` и `git stash --all`) удаляет файлы заметок. Агент такие команды не выполняет. Если их выполните вы, следующая сессия восстановит файлы из ветки, но незакоммиченные изменения заметок пропадут.
- Защита от push — это git-хук. Он не останавливает `git push --no-verify` и не копируется при клонировании.
- Менеджеры хуков вроде husky могут пересоздавать хуки. Агент перепроверяет защиту в каждой сессии.
- Заметки коммитятся от вашего git-имени. Если `user.name` или `user.email` не заданы, агент попросит вас их задать.
- Скрипты лежат в `.git/wzrdlog/`, и агент пересоздаёт их, если они пропали.
