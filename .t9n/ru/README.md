# WZRDLOG — промпт AGENTS.md для ИИ-агентов, которые пишут код

`AGENTS.md` делает из ИИ-агента дисциплинированного исполнителя с памятью. Агент ведёт рабочие
заметки в файлах `WZRDLOG*`: задача, roadmap, неудачи, удачи, ограничения, переиспользуемые
фрагменты и словарь ваших терминов. Он версионирует их в **только локальной** git-ветке
`WZRDLOG`, а вашу настоящую историю оставляет чистой.

## Зачем

- Агенты всё забывают между сессиями. WZRDLOG даёт им память, которая переживает сессии и имеет свою историю в git.
- Агенты повторяют неудачные подходы. WZRDLOG заставляет записывать неудачи и перечитывать их.
- Агенты слишком охотно делают push и публикуют. WZRDLOG держит git локальным, хуком запрещает push заметок и не пускает их в npm.
- Длинные промпты игнорируются. AGENTS.md — это чеклист с проверками и точными командами, а не проза.

## Быстрый старт

1. Скопируйте `AGENTS.md` (и при желании `HUMANS.md`) в корень своего проекта.
2. Если ваш агент сам не читает `AGENTS.md`, укажите на него. Для Claude Code создайте `CLAUDE.md` с одной строкой:
   ```md
   @AGENTS.md
   ```
3. Начните сессию. При первом запуске агент:
   - проверит папку и при необходимости выполнит `git init`;
   - добавит `WZRDLOG*` в `.gitignore`;
   - установит защитный хук `pre-push` и свои скрипты в `.git/wzrdlog/`;
   - один раз спросит о предпочтениях по языку и дизайну.

## У вас уже есть AGENTS.md

- Оставьте правила своего проекта в начале `AGENTS.md`, а ниже вставьте протокол WZRDLOG — от `# AGENTS.md — WZRDLOG protocol` до конца. Протокол самодостаточен и разбит на пронумерованные разделы, поэтому не зависит от того, что написано выше.
- Не сохраняйте протокол в файл, имя которого начинается с `WZRDLOG`. Такой файл попадёт под `WZRDLOG*` и будет проигнорирован git.
- Если в проекте уже есть свой `HUMANS.md`, агент его тоже читать не будет. Всё, что агенту нужно знать, перенесите в `AGENTS.md`.
- `CLAUDE.md`, `.cursorrules` и подобные файлы можно оставить. Пусть они ссылаются на `AGENTS.md`, а не дублируют его.

## Стоимость

Протокол не бесплатен по токенам. Учитывайте это:

- `AGENTS.md` — около 340 строк (примерно 4–5 тыс. токенов), и он читается в начале каждой сессии.
- При старте агент также читает `WZRDLOG_BY_OPERATOR.md`, `WZRDLOG_AND_TERMS.md`, `WZRDLOG.md`, `WZRDLOG+roadmap.md`, `WZRDLOG+failures.md` и тематические файлы под задачу. Они растут вместе с проектом.
- Сжатие (раздел 10 в `AGENTS.md`) держит эти файлы короткими. Старое уходит в историю ветки `WZRDLOG` и ничего не стоит, пока не понадобится.
- Взамен агент не изучает проект заново и не повторяет известные неудачи, а это обычно обходится дороже.

## Ключевые идеи

- **Две истории в одном репозитории.** Код идёт в ваши ветки, заметки — в ветку `WZRDLOG`, которую никогда не пушат.
- **Чеклисты с проверками.** Каждый шаг — вопрос «да/нет» и действие, поэтому агент не может перескочить вперёд.
- **Канонические термины.** Вы говорите как удобно, а имена файлов остаются стабильными.
- **Измеримые примитивы.** У `WZRDLOG+substr-domain-13.js` 13 строительных блоков, они перечислены в его заголовке. Оптимизация видна по уменьшению числа.
- **Архив, а не склад.** Старое удаляется, и на него ссылаются как `file@hash:L10-L20`.

## Требования

- git и POSIX-совместимый `sh` (на Windows — Git Bash).
- Настроенные в git `user.name` и `user.email`.
